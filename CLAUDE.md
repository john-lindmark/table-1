## Rules that must hold
- **Server-authoritative rules.** Pairings in `events-engine`, standings from a Postgres function. Clients render and submit only. Standings are computed from results, never stored.
- A match holds *sides*, not player_a/player_b. Pods are first-class even with one pod. Every mutation writes an audit row.
- Claim tokens live in `participant_tokens` (RLS on, no policy). Event location lives in `event_locations`.
- Event tables (events, event_members, event_teams, pods, participants, rounds, matches, match_sides, audit_log) are RPC-only: no client write policy or grant (2026-10-17, `contract/rpc-only-writes-2026-10-17.md`). A new write needs a security definer RPC that audits itself. Clients can only link a participant to their own account.
- Results: single entry counts; opponent's same score confirms, different score disputes; auto-confirm at round end; organizer can override (audited). Unresolved disputes block pairing the next round.
- Tournament rules follow the WPN Magic Tournament Rules (Feb 27 2026): 3/1/0 match points, bye 3, OMW/GW/OGW with 33% floor. Open: Appendix E recommended-rounds table is unconfirmed.
- Auth: Sign in with Apple + Google + Discord + email (passwordless code and link, built 2026-10-15 on all clients; `contract/email-sign-in-2026-10-15.md`; Discord 2026-10-29, `contract/discord-sign-in-2026-10-29.md`). The email link `https://table-1.site/auth/confirm` opens the app via universal/app links. Account deletion must revoke the Apple token.
- Demo data is `is_demo`, seeded and shown only for accounts in `t1_private.demo_testers` (server-enforced, any build), and never in real records.
- Credits/efficiency: avoid full three-platform builds per change. Build order (John, 2026-10-14): iOS first, then web, then Android, in batches.
- Test iOS changes in the Simulator in Debug. Other Claude sessions build and run here too: use your own simulator device and your own `-derivedDataPath` (e.g. in your scratchpad), never shut down or reuse a simulator another session booted.

- **Design guidance: `table-1-context/docs/design-guidance-2026-11-01.md`** (John, 2026-11-01), written from the frames he designed himself in the screens file: life tracker 73:5420 / 92:659 / 92:749, Collection home 325:10820, card detail 318:10810, Account 455:9946, tab bar 407:9333. - **The thing itself first, nothing explains itself, go deeper not longer.** A screen opens on its subject, large (the card, the life total, the art, the record) with one bar and one bottom bar. No bar subtitles, no row descriptions, no paragraphs saying what a screen is for; labels are codes (`MH2 · EN · NM · NF`), a second line is data only. Everything else is one tap away on its own screen: attribute cells open pickers, Add to drills down, details sit behind the list icon, a tab root hides the rest behind `+`, search and the gear. Stacked sections on one long screen are the old pattern; bring a screen to the guidance whenever it is touched (the guide § 7 lists what changes).
- **Icons say it.** Material Symbols **Sharp, weight 300**, no fill, grade 0, optical size 24, drawn from their paths in an 18 pt box (iOS `T1Icon`, web `ICON`/`TAB_ICON`, Android `T1Icon`); add a new icon to all three clients in one commit, named after the symbol. Bar actions, shelf headers, steppers and the tab bar are icons; words stay for a screen's one big action (`ADD TO`) and picker options. No SF Symbols, no Material theme icons, no emoji.
- Table 1 components everywhere (bars, tab bars, pickers, steppers, switches, menus, sheets). Only alert dialogs (and Android's date picker) are platform-native.
- Look: SF Mono (JetBrains Mono stands in inside Figma), uppercase labels with wide tracking, zero radius, no shadows/cards, 1 px hairline grid, dark `#171725`, surface `#282839`, muted `#c4c4ca`, one accent teal `#00ffd9` meaning "the result" or "the current choice" (an outline or line, never a routine button fill), disabled = flat `#545461` fill (no opacity dimming; the card detail stepper's 40 % is an open question in the guide), art under a 60 % scrim as the only texture.
- Spelling: "color", never "colour" (John, 2026-11-01), in copy, UI strings, server text and code on every platform.
