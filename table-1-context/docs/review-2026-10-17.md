## Security

Sources: Supabase advisors (security + performance), `pg_policies`, table grants, edge function code.

### S1. Organizer write policies bypass the RPC layer (high)
`events`, `matches`, `match_sides`, `participants`, `rounds`, `pods`, `event_members` each have a `*_organizer_write` policy `FOR ALL TO public` gated only by `is_event_organizer()`, and `authenticated` holds INSERT/UPDATE/DELETE grants on them. `audit_log` has an organizer INSERT policy. So anyone who creates an event can, through plain PostgREST:
- set any match's result or status with no `report_match`/dispute flow and **no audit row** (and can insert fake audit rows);
- insert a `participants` row with **any user's id** (profile ids are readable by anyone, see S3), add matches and sides, and the `matches_records_sync` / `match_sides_records_sync` triggers write the result into that user's global `player_records` and `head_to_head`;
- insert `events` directly (`events_insert_authenticated`), skipping `create_event_v2` validation.

Clients rely on some of this today, so the fix needs RPCs first:
- `apps/ios/Table1/Data/Repo.swift:244` and `apps/android/.../data/Repo.kt:370-375` update `rounds` then `events.status` directly, as two non-atomic calls (a failure between them leaves a recorded final round on a running event).
- `apps/android/.../data/Repo.kt:362` updates `participants.status` directly (drop/reinstate).
- `table-1-events-web/src/lib/api.ts:655` writes `audit_log` from the client, separately from the change it describes.

Fix: add `record_round(p_round_id, p_final)` and `set_participant_status(...)` RPCs that write their own audit rows; move every client to them; then drop the `*_organizer_write` and `events_insert_authenticated` policies, revoke INSERT/UPDATE/DELETE on those tables from `anon`/`authenticated`, and make `audit_log` writable only from definer functions. Add an invariant to `supabase/tests/30_security_test.sql`: no write policy or write grant for client roles on event tables. Separately, only count matches in `player_records` for participants whose `user_id` came from a claim/join/accepted invite, not one an organizer typed. Bonus: removes all 36 "multiple permissive policies" performance warnings.

### S2. `list-import` cost and SSRF (medium)
`supabase/functions/list-import/index.ts`:
- No per-account limit. Any unknown URL goes to `anyPage`, which sends up to 120k characters to `claude-opus-5-5` with `max_tokens: 16000`. `deck-finder` has `deck_finder_take` (20/day); reuse it here.
- `fetch(u, { redirect: "follow" })` follows redirects to hosts the private-address check never sees, and hostnames that resolve to private IPs (e.g. `*.nip.io`) pass the regex. Use `redirect: "manual"` and re-check each hop, or restrict link imports to known deck sites.
- `host.endsWith("cubecobra.com")` also matches `evilcubecobra.com` (`cube-lookup` already uses the right `(^|\.)` pattern).
- Extraction is a good fit for a smaller model (Haiku/Sonnet): faster imports, a fraction of the cost.

### S3. Public reads (decide deliberately)
`anon` can read every row of `profiles` (id, handle, display name), `participants`, `matches`, `match_sides`, `events` (including demo and cancelled events and `venue_name`), `player_records`, `head_to_head`, `event_results`, `standings_snapshots`. So anyone can scrape every player's lifetime record and every rivalry. If public standings (`PublicStandings.tsx`) is the reason, serve it from a definer RPC keyed by the event's short code, and limit direct reads to events you're in. `event_locations` and `participant_tokens` are correctly locked.

### S4. Smaller items
- **Password sign-in.** "Leaked password protection" is off. If only OTP/magic link, Apple and Google are used, turn off email+password sign-up in Auth so the warning doesn't matter; otherwise turn the protection on.
- **Leftover tables.** `kv_store_82efb40a` and `kv_store_a539856f` (Figma Make leftovers) carry 19 duplicate indexes. Drop them.
- **Defense in depth.** `authenticated` holds INSERT/UPDATE/DELETE on `collection_items`, `collection_ledger`, `library_summary`, `trades`, `card_lists`, `cards`, `card_prices`, `mtg_sets`, `format_points`, `roto_*`, `rpc_idempotency`, … RLS blocks them today, but one careless permissive policy would open them. Revoke and test.
- **Helpers callable by anon.** `is_event_organizer`, `tracker_visible`, `get_event_teams`, `catalog_info`. Harmless today; revoke `anon` on helper functions as a rule.
- **Scan reports** outlive account deletion (OCR text only). Say so in the privacy policy.

## Performance

| # | Finding | Suggestion |
|---|---|---|
| P1 | Catalog pack is 8.3 MB gzip and re-downloaded in full on every version; three old versions stay in the bucket | Split stable (oracle text, names) from volatile (new printings, legality), or ship deltas against the previous version; delete superseded packs after N days |
| P2 | `card_prices` keeps only today's price | Daily snapshots (only printings someone owns or wants, delta-encoded) unlock history charts, value over time, gainers/losers, alerts |
| P3 | 36 multiple-permissive-policy warnings on event tables | Disappear with the S1 fix |
| P4 | Unindexed FKs: `event_deck_photos.participant_id`, `event_redraft_cards.card_id`, `roto_pool.card_id` | Add the three indexes. Ignore the 32 "unused index" warnings until there's real traffic |
| P5 | Auth uses a fixed 10 DB connections | Switch to a percentage before upgrading the instance |
| P6 | Crons every minute (`t1-notify-sweep`, `t1-roto-expire`) and every 2 min (`t1-catalog-tick`) | Confirm each exits in a few ms when idle; add them to `./test.sh perf` |
| P7 | `list-import` link reads take tens of seconds on Opus | Smaller model; parse known sites (Archidekt, Cube Cobra, Goldfish) without a model, as now |
| P8 | Event rounds and completion are two client calls (S1) | One RPC = one round trip and atomic |

The perf budgets in `TESTING.md` are healthy (search 18–23 ms, `collection_apply` 500 ops 80 ms).

### Roadmap, in order
1. **Collection import.** Parse CSVs from ManaBox, Moxfield, Archidekt, Deckbox, Dragon Shield, TCGplayer, Delver by header detection (name + set/collector number minimum, plus finish, condition, language, qty). Show a preview with unmatched lines, then one `collection_apply` batch (`source: import`) with Undo. Your plan already names this (Current direction #4).
2. **Export.** Collection CSV in Moxfield and ManaBox column layouts; decks as Arena/MTGO/plain text; cubes as Cube Cobra CSV. Put it on web first.
3. **Binders and wants.**
   - Binders: a named location per copy ("Trade binder", "Box 3"). Model it as an allocation of item quantities to binders, not a new key on the item, so the ledger and sync stay as they are.
   - "For trade" is a binder flag. Trades' "give" then defaults to trade-binder copies.
   - Wants: a list kind (or an auto-list of every deck's Missing) with an optional target price.
4. **Search.** Scryfall syntax over the local SQLite catalog (`t:`, `c:`/`id:`, `o:`, `mv`, `r:`, `set:`, `is:foil`, `f:`), plus saved filters. Everything is offline already, so this is client work across three platforms (or one shared parser spec plus tests).
5. **Deck tools.** Curve (spells vs permanents), color pips vs mana sources, type counts, average MV, legality with the reason (codes are already in the pack), tokens, sample 7 with mulligan, hypergeometric "odds of X by turn N". Cubes: color balance, curve per color, Asfan, a sample pack.
6. **Prices.** Daily snapshots (P2) → 30/90-day charts, collection value over time, gainers/losers, alerts on wants. Add Card Kingdom and Cardhoarder (both in Scryfall's price data), plus multi-currency.
7. **Sharing.** Public/unlisted links on table-1.site for decks, cubes and the trade binder, with link previews. Show cube versions as a changelog with diffs (the data exists).

### Where Table 1 can beat them (nobody else has the events)
- **Deck records.** Register a Library deck for an event and its record follows it ("Izzet Phoenix · 5 events · 11-4"). Matchups go under Insights (progressive disclosure).
- **Cube per-card performance.** Roto and draft events already know each player's picks and results. Show per-card and per-archetype win rates, and redraft piles. Cube Cobra's equivalent is hand-logged.
- **Decklist submission.** Melee and Spicerack offer it for competitive events: legality checked from the pack, hidden until the event ends, archetype tags, a metagame breakdown for the organizer. Deck photos are a start.
- **Trades between two accounts at the event.** Both sides confirm and both collections update. "Who here has my wants in their trade binder" across an event's players turns event night into trade night.
- **Sync as a selling point.** ManaBox reviews include data loss with no backup, and pricing complaints are common. Server-backed history plus free export is the answer.
