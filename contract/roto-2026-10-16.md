# Roto: client contract (R0, 2026-10-16)

Server live: migration `20261016220000_roto.sql`, events-engine v7. Plan and decisions:
`table-1-context/docs/plan-roto-2026-10-15.md`. Wire shapes: `contract/rpc.schema.json` (`roto_*`, `create_event_v2`,
`update_event_details`, realtime `roto`). Checks: `supabase/tests/20_roto_test.sql` (95 passing, run in a transaction that
always rolls back) and `supabase/functions/events-engine/roundrobin.test.ts` (`node --test` or `deno test`).

## The event
- `format_name = 'roto'`, always a cube (`p_cube_name` required, a set is refused). `format` is `cube`, label
  "Roto · <cube>", automatic name as other events.
- `events.pairing`: `swiss` | `round_robin`. Round robin is roto only for now; `create_event_v2` defaults a roto to
  `round_robin` when `p_pairing` is null. Clients prefill Round robin for 2–8 players and Swiss for 9+, editable until
  round 1 (`update_event_details(..., p_pairing)`). With round robin the Rounds stepper is hidden; events-engine sets
  `number_of_rounds` (n − 1, or n when odd) when it pairs round 1.
- One pod, no player cap; the cube's Main board must hold players × picks per player.

## Phases
`roto_state.phase`: `setup` → `drafting` → `done`. Then rounds work exactly as for every event (pair_round, report,
confirm/dispute, standings). `pair_round` refuses round 1 until the draft is done ("Finish the draft before pairing
round 1"). Once drafting starts, players and seats are locked (adding, removing, re-seating and dropping fail with
55000 until the draft is done; dropping works again afterwards).

## Organizer flow
1. Create (format Roto, cube name/link as today, Pairing control).
2. Setup → Details: pick one of your Library cubes → `roto_set_cube(event, list_id)` → `{pool_count, players,
   max_picks_per_player}`. A Cube Cobra link goes through `list-import` into Library first, then `roto_set_cube`.
   Picks-per-player stepper (default 45, max from the answer), Order (Snake / Same order), Pick clock.
3. Pick clock: `roto_set_clock(event, [{from_round, seconds}, …])`. 1–10 ranges, first from round 1, 30 s to 24 h.
   `[]` clears. `p_paused` true/false pauses/resumes. Editable during the draft; the current turn keeps its time.
4. **Start draft** → `roto_start(event, picks_per_player, order)` (seats everyone at random unless already seated) →
   full state.
5. During the draft: **Pick for <name>** is `roto_pick` by an organizer; **Undo last pick** is `roto_undo` (removes the
   last pick a person made and the automatic picks after it; no auto-picks run afterwards).

## Player flow
- Load: `roto_state(event)` (pool included). Keep `pool` (slot → card_id, finish), `picks`, `seats`, `me`.
- Realtime: subscribe to broadcast topic `roto:<event_id>`, event `roto_changed`. On each message call
  `roto_state(event, p_after_pick = last pick you hold)`; append `picks`; if `draft.picks_made` is below what you hold
  (undo), drop picks above it. Also refresh on foreground.
- Pick: `roto_pick(event, slot, pick_no = draft.picks_made + 1)`. `{ok: true, state}` carries your pick and any
  auto-picks after it. `{ok: false, conflict: true, state}` means someone picked first: merge the state and let the
  player look again. Never retry blindly.
- Pick list: `roto_queue_set(event, slots[], auto_pick?)`, the whole list each time, debounced ~600 ms. The answer is
  the list as the server kept it (taken cards dropped). Taken cards leave everyone's list at once.
- Clock: `on_clock.deadline` (epoch s) or `remaining_seconds` while paused; `overdue` when past it with nothing listed.
  When a countdown reaches zero, any client in the event calls `roto_expire(event)` (pg_cron also sweeps every minute).
- Your deck: `me.deck_list_id` is a normal Library deck (lists contract) that fills as you pick (Main board).
  `lists_changes` rows now carry `event_id` and `event_name`: show "FROM <EVENT>" and never count Missing for them.
  Deleting it in Library only unlinks it. A guest who claims their seat later gets the deck at once.

## Views (Draft phase; Table 1 segmented control)
Summary line always on top: `ON THE CLOCK · <NAME> · PICK 37/360` + `YOU PICK IN n` / `YOUR PICK` (accent) + clock.
1. **Grid**: seats × rounds; snake arrows; cell = card name + colour bar, `auto` marker; next cell outlined accent.
2. **Cube**: pool grouped by colour, `Available · All · Picked`, picked rows carry `#23 · ANNA` in flat `#545461`.
3. **Picks**: one player's picks (You first), colour counts, curve; **Open deck** for you.
4. **My list**: ranked list, drag to reorder, Auto-pick switch, "Taken by …" shown once.
Seat number from `picks[i][1]` indexes `seats`; `seat` is 1-based pick order.

## Performance (measured 2026-10-16, 8 × 45 from 360, server time)
`roto_pick` ≈ 11 ms including the deck write and audit; `roto_state` full 5 ms / 26 KB (pool included), delta 1.3 ms;
`roto_queue_set` with 200 cards 15 ms. Client targets: tap-to-render a pick under 300 ms on a normal connection
(render optimistically, replace with the answer); first Draft load under 1 s; Grid (up to 12 × 45 cells) at 60 fps:
lazy rows, card names and colours from the local catalog only, images only in card detail and the Picks image grid.
Never refetch the pool after the first load; fetch picks by delta only.

## Telemetry (PostHog; names in `telemetry-2026-10-15.md`)
Screens `roto_grid`, `roto_cube`, `roto_picks`, `roto_list`. Events, fired after the server accepts:
`roto_cube_set`, `roto_started`, `roto_picked`, `roto_list_changed`, `roto_clock_changed`, `roto_pick_undone`,
`roto_deck_opened`; `event_created` and `round_paired` gain `pairing`. Sentry spans: `roto.state` (first load and
delta), `roto.pick` (tap to answer), and Grid first render. Business numbers (picks by how, timeouts, undo) come from
Postgres (`roto_picks.how`, `audit_log` actions `roto.*`), not PostHog.
