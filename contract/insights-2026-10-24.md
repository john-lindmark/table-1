# Insights: constructed metagame and Arena draft (2026-10-24)

Client and server contract for the Insights tab. Plan and decisions: `table-1-context/docs/plan-insights-2026-10-24.md`.
Wire names are exact (snake_case on RPCs; the packs use the short keys below to stay small).

## What the viewer gets

An **Insights** tab next to Events and Collection (fourth tab, before Account), on every platform, signed in. It opens
on **Constructed | Limited** (Table 1 segmented control), remembered per device.

- **Constructed:** a format picker (Standard, Pioneer, Modern, Pauper, Canlander: one row of whole words that scrolls
  sideways on a phone, the picked format in view; **Edit** at its end lists every format with a switch, so a viewer
  can keep formats out of the row, never the last one, kept on the device: `hiddenFormats`), **Big events | All events**, and a window
  (**7D 14D 30D 90D**, default 30D). Then, top to bottom: the **brief**, **Meta now** (share bars with change),
  **Meta over time** (share lines with ban and set markers), **Cards** (rising / falling, Main | Side), **New set**,
  **Bans** (one row per format change → ban study), **Matchups** (grid), **Big events**. Archetype and card rows open
  their own screens.
- **Limited:** a set picker (every set on Arena with a 17Lands dump, scrolling like the format row, with the same **Edit**:
  `hiddenSets`), an event picker (Premier, Traditional, Pick Two,
  Sealed; only those with data), **All players | Top players**. Then the **brief**, **Colour pairs** (bars against the
  set average), **Deck colours** (every main colour combination with its splash), **Pairs by week** (lines), **Cards** (sortable: GIH WR, OH WR, IWD, ATA; rarity and colour filters),
  **Taken vs win rate** (scatter with a fitted line), **Game facts**. A pair row opens the pair screen; a card row the
  Limited card screen.
- Every Limited screen shows **"Data from 17Lands"** at the top with a link to https://www.17lands.com/public_datasets.
  Constructed screens credit the pack's `sources` under the brief (`sourcesCredit` on every client): **"Results from
  Magic Online"**; **"Results from Magic Online and TopDeck.gg"** once any TopDeck event is in the pack; **"Results
  from TopDeck.gg"** when TopDeck is the only source (Canadian Highlander). Any TopDeck credit links to
  https://topdeck.gg. Never suggest either endorses Table 1.
- No player names anywhere. Insights is free.

## Sources and tiers

| source | read | what |
|---|---|---|
| `mtgo` | mtgo.com/decklists month pages, then each event page's `window.MTGO.decklists.data` | Challenges, Showcase Challenges, RC Super Qualifiers, Championship-week events (standings, W-L, top 8 bracket, decklists); Leagues (published 5-0 lists) |
| `topdeck` | `POST https://topdeck.gg/api/v2/tournaments` with the key from the `TOPDECK.GG_KEY` function secret (or `TOPDECK_API_KEY`, or `t1_private.settings` `topdeck_api_key`); skipped without one | paper events of 32+ players (16+ for Canadian Highlander, `meta_formats.topdeck_min`): standings, decklists once public, every round. Each build reads the last 3 days; each tick also reads up to 40 s of the past year in 30-day windows (`td_back_<format>` cursors in `meta_state`, TopDeck-only formats first) until a year is read |

**Formats** live in `t1_private.meta_formats` (`format`, `name`, `ord`, `enabled`, `topdeck` name, `topdeck_min`,
`legality`: the Scryfall legality key when it isn't the format's own) and reach meta-sync through
`meta_formats_enabled()` (service role). Enabled: Standard, Pioneer, Modern, Pauper (MTGO + TopDeck) and **Canadian
Highlander** (`canlander`, 2026-10-25: TopDeck only, as MTGO has none; set releases and the New set panel use Vintage
legality; its bans come from its own list and aren't tracked).

Tier (stored on the event):

| tier | rule | weight |
|---|---|---|
| `major` | 128+ players, or a Showcase Challenge, RC Super Qualifier or Championship-week event | 4 |
| `large` | 64–127 players | 2 |
| `regular` | 32–63 players | 1 |
| `small` | under 32 players, and every League | 0.5 |

A deck's weight is its event's tier weight, doubled for a top-8 finish. **Big events** = `major` + `large`; **All
events** = every tier. Shares are weighted shares of the decks published, so MTGO numbers are "share of top
finishes" (Challenges publish the top 32). A window is **thin** when its weighted decks are under 40; the client
greys the window's charts and the brief says so. When the 30-day window of Big events is thin the client opens on
All events (`default_tier` in the pack).

## Archetypes

`meta_archetypes`: `id`, `format`, `name`, `family` (`aggro` | `midrange` | `control` | `combo` | `ramp`), `colors`
(WUBRG order, `""` colourless), `status` (`approved` | `proposed` | `retired`), `rule`, `priority` (lower first),
`source` (`seed` | `claude` | `john`).

`rule` (card names, matched case- and accent-insensitively on the front face):

```json
{ "colors": "WUB",                  // exactly these deck colours (WUBRG order; "" colourless), optional
  "main": ["Card", "..."],          // all of these in the main deck
  "any": [["A", "B"], ["C", "D"]],  // at least one of each group, main or sideboard
  "deck": ["Card"],                  // all of these in main or sideboard
  "not": ["Card"] }                  // none of these anywhere
```

A deck's colours are those with 4+ nonland cards of them in its main deck. Singleton formats share few cards between
lists, so Canadian Highlander's rules are by colours: a named plan per colour group seen in 5+ public lists (Esper
Control, Bant Midrange, Red Deck Wins, Rakdos Midrange, Jund Midrange, Sultai Midrange, Abzan Midrange, Boros Aggro,
Azorius Control, Dimir Tempo, Grixis Tempo, Jeskai Black, Four-Color Control; priority 50) and the colours' own names
for the rest (Izzet, Naya, Mono-White…; priority 60).

Rules run in `priority` order; the first match wins. A deck matching none gets id `0`: **Other** (with its colours in
`colors`). Only `approved` archetypes label decks; clients only ever see approved ones. Relabelling runs over every
stored deck whenever a rule changes, so history follows the current rules.

## Format changes

`meta_format_changes`: `id`, `format`, `on` (date), `kind` (`ban` | `unban` | `restrict` | `unrestrict` |
`set_release` | `rotation` | `points`), `cards` (names), `set_code`, `note`, `url`, `status` (`confirmed` | `proposed` |
`rejected`), `detail` (points: `[{n, before, after}]`). Bans in the last 12 months were entered from Wizards' announcements; new ones are proposed by a daily
diff of the catalog's legalities and confirmed by a moderator. Set releases are added for expansion, core and
draft-innovation sets as they release; only confirmed changes reach clients.

**Points** (Canadian Highlander, 2026-10-26): its points list (canadianhighlander.ca, read with every catalog build by
`format_points_replace`) takes the place of bans. Each card whose points move is logged (`meta_points_log`); the daily
proposer makes a day's moves one `points` change, with `note` in words ("Mana Crypt 3 → 4, Gush 0 → 1") and `detail`,
confirmed when 15 cards or fewer moved and proposed for Review when more did (a list read half-wrong). Points changes
get ban studies: cards that gained points are treated like bans (decks that held them, who lost share), cards that
lost points like unbans (who picked them up). Clients mark them **POINTS** on the charts, word them "Points: …" and
head the studies **Points changes** (`bansTitle`). The site keeps no history, so changes start from the list read on
2026-10-25.

## Packs

Clients read one **pack** per format and per Limited set, published to the public `catalog` bucket under
`insights/`, plus a few RPCs for the deeper screens.

### `insights_index()` → array (authenticated)

```json
[{ "kind": "constructed", "key": "modern", "name": "Modern", "version": "c-3f2a91b0d4e1",
   "url": "https://…/storage/v1/object/public/catalog/insights/constructed/modern.json",
   "bytes": 184211, "built_at": "2026-10-25T06:12:00Z", "through": "2026-10-24" },
 { "kind": "limited", "key": "FRA", "name": "…", "version": "l-…", "url": "…/insights/limited/FRA.json", … }]
```

Constructed entries in format order (standard, pioneer, modern, pauper); Limited newest set first. A client keeps
the last pack of each key on the device and refetches only when `version` changes (`If-None-Match` too).

### Constructed pack

```jsonc
{ "v": 1, "kind": "constructed", "format": "modern", "name": "Modern", "built_at": "…", "through": "2026-10-24",
  "sources": ["mtgo"],                    // "topdeck" once any TopDeck event is in
  "default_tier": "big",                  // "all" when Big events' 30-day window is thin
  "archetypes": [{ "id": 12, "name": "Boros Energy", "family": "aggro", "colors": "RW" }],   // id 0 = Other
  "changes": [{ "id": 3, "on": "2026-05-18", "kind": "ban", "cards": ["Lotus Field"], "set_code": null,
                "note": null, "url": "https://magic.wizards.com/…" }],
  "tiers": { "big": View, "all": View },
  "bans": [BanStudy],                     // every confirmed ban/unban in the last 12 months, newest first (All events)
  "matchups": Matchups,                   // 90 days, All events
  "events": [{ "name": "Modern Challenge 64", "on": "2026-10-21", "players": 71, "tier": "large",
               "source": "mtgo", "url": "https://www.mtgo.com/decklist/…",
               "top8": [12, 12, 4, 7, 0, 3, 12, 9], "winner": 12 }] }   // last 30 days, Major+Large first, at most 40
```

`View` (one per tier):

```jsonc
{ "windows": { "7": Window, "14": Window, "30": Window, "90": Window },
  "series": { "from": "2026-04-28", "days": 180,              // one value per day, oldest first
              "lines": [{ "a": 12, "v": [0.21, 0.22, null, …] }],  // 7-day rolling weighted share; null = no decks
              "other": [0.31, …] },                            // everything not in lines (incl. id 0)
  "new_set": { "set_code": "fra", "name": "…", "released": "2026-09-26",
               "cards": [{ "c": "oracle-uuid", "n": "Card", "rate": 0.18, "copies": 2.6, "in": [12, 4] }] } | null }
```

`series.lines` holds the 8 archetypes with the largest 30-day share in that tier.

`Window`:

```jsonc
{ "decks": 812, "weighted": 1093.5, "events": 41, "thin": false,
  "brief": "Two or three sentences." | null,
  "share": [{ "a": 12, "share": 0.214, "prev": 0.188, "decks": 160, "top8": 22, "conv": 1.31 | null }],
  "cards": { "main": { "up": [Card], "down": [Card] }, "side": { "up": [Card], "down": [Card] } } }
```

- `share` holds every archetype with a deck in the window, largest first; `prev` is the same-length window before it
  (null when that window has no decks). `conv` is top-8 share ÷ share where every deck of the events is known
  (TopDeck with all decklists public) and the archetype has at least 20 decks there, else null.
- `Card`: `{ "c": "oracle-uuid", "n": "Card", "rate": 0.31, "prev": 0.22, "copies": 3.4 }`. `rate` is the weighted
  share of decks playing the card (main or side, per list); `copies` the average count in those decks. `up`/`down`:
  the 12 largest rises and falls by `rate - prev`, cards in at least 3% of decks in either window; basic lands never.

`BanStudy`:

```jsonc
{ "change": 3, "on": "2026-05-18",
  "before": [{ "a": 12, "share": 0.27 }],                 // 30 days before: every archetype at 0.5%+ (at most 20)
  "after": { "14": [{ "a": 12, "share": 0.09 }], "30": […], "60": […] },   // windows that have ended; same rule
  "losers": [{ "a": 12, "before": 0.27, "after": 0.09 }],  // held a changed card in ≥50% of lists before
  "gainers": [{ "a": 4, "before": 0.08, "after": 0.15 }],  // the 3 largest gains
  "replacements": [{ "c": "uuid", "n": "Card", "before": 0.02, "after": 0.41, "in": 12 }],  // per loser, top 3
  "settled_days": 19 | null,                               // first day 7-day shares stay within 2 pts for 7 days
  "brief": "…" | null }
```

"after" uses the longest ended window up to 60 days (or the days so far). An unban study has no losers; its
`replacements` list the unbanned card's adoption by archetype. Other (id 0) is never a loser or gainer. A change
with no decks before it and none after (older than the data) is left out.

`Matchups`: `{ "archetypes": [12, 4, …], "cells": [[12, 4, 31, 22, 1], …] }` — each cell is
`[a, b, a_wins, b_wins, draws]` for matches between decks of a and b (TopDeck rounds where both lists are known, and
MTGO top-8 brackets), a < b by position in `archetypes` (top 10 by 90-day share). Clients show a cell only when it
has at least 30 matches, with its 90% Wilson interval.

### Limited pack

```jsonc
{ "v": 1, "kind": "limited", "set_code": "FRA", "name": "…", "released": "2026-09-23", "built_at": "…",
  "credit": { "name": "17Lands", "url": "https://www.17lands.com/public_datasets" },
  "events": { "PremierDraft": { "updated": "2026-10-17", "groups": { "all": LView, "top": LView } }, … } }
```

`top` = players whose 17Lands win-rate bucket is 60% or more with at least 50 games (labelled "Top players (60%+)").

`LView`:

```jsonc
{ "games": 312004, "wr": 0.553, "weeks": 4, "brief": "…" | null,
  "pairs": [{ "p": "UB", "games": 41022, "wr": 0.571, "share": 0.131, "splash": 0.22,
             "play_wr": 0.59, "draw_wr": 0.55, "week_wr": [0.55, 0.56, …], "week_share": [0.10, …] }],
  "cards": [{ "c": "uuid" | null, "n": "Card", "r": "common", "col": "U",
             "gih": 0.601, "gih_n": 28010, "oh": 0.612, "gd": 0.594, "gns": 0.541, "iwd": 0.06,
             "ata": 4.21 | null, "deck": 0.18, "week_gih": [0.58, …], "pair_gih": { "UB": 0.63 } }],
  "colors": [{ "m": "UB", "s": "R", "games": 12040, "wr": 0.571, "share": 0.04 }],   // deck colours, below
  "facts": { "play_wr": 0.561, "draw_wr": 0.545, "mull_rate": 0.091, "keep7_wr": 0.557, "mull_wr": 0.47,
             "turns": 9.4, "mull_play": 0.09 } }
```

- Win rates are game win rates. `gih` = games in hand (opening hand or drawn); `gns` = in the deck, not seen;
  `iwd` = gih − gns; `deck` = share of games with the card in the deck. A card with fewer than 500 games in hand has
  null rates (still listed, greyed). `pair_gih` only where the pair has 200+ such games.
- `pairs`: two-colour pairs by `main_colors`, plus mono colours, plus `"3C"` for three or more; `share` of all games.
  Clients list pairs with at least 1% of games (a mono colour on 0.3% of games isn't the best pair).
- `colors` (2026-10-25): 17Lands' deck colour table from the public game data: each exact `main_colors` (WUBRG order,
  three and more colours kept as written) with its `splash_colors` (`""` for none), on 0.5% of games or more, most
  played first. Clients name them "Dimir UB + r", "Esper WUB", "Four-colour WUBR" and list the 15 most played.
- Weeks count from the set's release on Arena (week 1 = its first 7 days).
- `ata` (average pick it was taken at, 1–14 in a pack of the event's size) comes from draft data, null until that
  dump has been read.

## RPCs

All `authenticated`, security definer, stable; none raise 40001/40P01.

- `meta_archetype(p_format text, p_archetype int, p_tier text default 'all', p_days int default 30)` →
  `{ archetype, series: { from, weeks: 26, v: [share per week] }, record: { wins, losses, draws, basis: "topdeck" |
  "mtgo_top32" | null }, conv, core: [Card + "main_rate"], flex: [Card], side: [Card], trending: { up, down },
  matchups: [{ vs, wins, losses, draws }], finishes: [{ event, on, players, tier, rank, url, main: [[name, qty]],
  side: [[name, qty]] }], brief }`. Core = main-deck cards in ≥80% of the window's lists; flex = 20–80%; side =
  sideboard cards in ≥20%; finishes = the 10 best weighted finishes, each list spells first and lands last. For Other
  (`p_archetype` 0) also `groups: [{ colors, decks, share, cards, example }]`: Other's decks by colours (up to 8, by
  share of Other), each group's 4 most-played nonland cards, and `example`, the index in `finishes` of its best list
  (added there when it isn't among the ten). Unknown format/archetype: 22023.
  Clients: a named archetype's page shows an **Example list** near the top (`exampleFinish`: the biggest event's tier,
  then the best finish, then the newest; whole lists only), its first 12 main-deck lines and **Add to my decks** (a new
  private deck in original printings, then Open); Other's page shows **Inside Other · by colours** instead of the
  core/flex/sideboard blocks, each group opening its example list, named for its colours when added. The matchup grid
  shows every pairing with matches; under 30 it's faded (half the fill, muted number: `heat` in the shared chart
  maths). Meta over time is 320 px tall on the web, 300 pt in the apps.
- `meta_card(p_format text, p_oracle_id uuid, p_tier text default 'all')` → `{ c, n, series: { from, weeks: 26,
  main: [rate], side: [rate] }, copies, by_archetype: [{ a, rate, copies }], first_seen }`. A card never seen: an
  empty series.
- `insights_review()` (moderators only, else 42501) → `{ archetypes: [proposed, with decks, sample: [[name, qty]]
  and signature], changes: [proposed], unmatched: [{ source, name, seen, last_seen }] }`.
- `insights_review_archetype(p_id int, p_action text, p_name text default null, p_family text default null)` —
  `approve` | `reject` | `rename`; approving relabels the format. Moderators only. Audited in
  `t1_private.insights_audit`.
- `insights_review_change(p_id int, p_action text)` — `confirm` | `reject`. Moderators only. Audited.

Worker RPCs (service role, called only by `meta-sync` and `limited-sync`) are listed in the migration.

## Briefs

Written by `claude-haiku-5-5` (low effort, JSON schema `{ "sentences": [string] }`) from a facts sheet the server
builds; never from decklists or names of people. Two or three sentences, at most 60 words. Before one is kept:
every number in it must appear in the facts (as written there), there are 2–3 sentences and ≤ 60 words, and a thin
window says so. A brief that fails is sent back once; failing again keeps the previous brief for that view (or
none). Cached in `t1_private.insight_briefs` by view key and a hash of the facts, so each brief is written once per
change in its facts.

Views with a brief: each tier × window of each format, each ban study, each of the top 8 archetypes (All events,
30D), and each Limited set × event × group.
