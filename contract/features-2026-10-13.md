# Client spec — life tracker, event types & formats, team events, Collection tab (2026-10-13)

Backend is live (migrations `20261013120000_formats_teams_tracker.sql`, events-engine with `seat_players`).
Every platform implements the same behavior below. Wire names are exact.

---------------------------------------------------------------------------------------------------
## 1. Navigation
Tabs: **Events | Collection | Account** (iOS TabView, Android NavigationBar, web TopNav).
Collection is visibly disabled (greyed, label "Collection", small "Soon") and cannot be selected:
- iOS: tab selection binding ignores `.collection` and briefly shows "Collection is coming soon".
- Android: `NavigationBarItem(enabled = false)`.
- Web: a non-link element styled muted with "Soon".

Events top bar gains **Life** (opens the life tracker with no event) next to **+ New**.

## 2. Event create (replaces the old single-screen form)
Steps on one scrolling form (native: Form/sections; web: stacked rows):

1. **Type**: segmented control `Constructed | Limited` (default Limited).
2. **Format**:
   - Constructed: Standard, Pioneer, Modern, Legacy, Vintage, Pauper, Premodern, Canadian Highlander, Other.
     "Other" shows a text field "Format name" (≤ 40 chars) → `p_format_other`.
   - Limited: Draft, Team draft, Sealed, Team sealed.
   Wire values (`p_format_name`): `standard pioneer modern legacy vintage pauper premodern canadian_highlander
   other_constructed draft team_draft sealed team_sealed`.
3. **Product** (Limited only): segmented `Set | Cube`.
   - Set: searchable list from `rpc draftable_sets(p_query text, p_limit int)` → rows `{code, name, set_type,
     released_at, icon_svg_uri}` newest first. Picking sets `p_set_code` (and `p_set_name` = name as fallback).
     If the list comes back empty, show a text field "Set name" and send it as `p_set_name` with `p_set_code` null.
   - Cube: "Cube name" (required, ≤ 80) → `p_cube_name`, "CubeCobra link (optional)" (must start https://) → `p_cube_url`.
4. **Teams** (Team draft / Team sealed only): segmented `3 | 4` players per team → `p_team_size`.
5. **Rounds**: stepper. Default 3 for team events; otherwise 3 (organizer can change, 1–15).
6. **Round length**: minutes, default 50.
7. Name (prefilled from format, e.g. "Modern night", "Duskmourn draft").
Location / visibility / players as before.

Create: `rpc create_event_v2(p_name, p_format_name, p_rounds, p_round_seconds, p_set_code, p_set_name,
p_cube_name, p_cube_url, p_team_size, p_format_other, p_player_names)` → `{event_id, short_code}`.
(Native apps then call set_event_location as today.) After create → event screen → Add players (as today).

Events carry new read-only columns: `format_name, format_label, event_type ('constructed'|'limited'), team_size,
set_code, set_name, cube_name, cube_url`. Everywhere an event's format was shown, show `format_label`
(e.g. "Modern", "Draft · Duskmourn", "Team draft · Vintage Cube"). `events_home` rows include
`format_name, format_label, event_type, team_size`; invites include `format_label`.

## 3. Draft seating (format_name `draft` or `team_draft`)
Organizer, before round 1 (status setup/seated, no rounds):
- **Seat players** button (Players tab, and the Round tab's empty state). Calls
  `rpc seat_event(p_event_id)` (2026-10-14; replaces the events-engine `seat_players` action, which now just wraps it) →
  `{event_id, pods: [{pod_id, name, seats: [{seat, participant_id, display_name, team}]}]}`.
  Calling it again re-shuffles. Pairing round 1 seats automatically if nobody is seated. Render the returned pods
  immediately and free the button; reload the event in the background. Errors: 42501 not organizer, 55000 locked /
  not a draft / team problems (show the message), 22023 no players.
- **Seating view** (organizer and players): for each pod, a numbered list (or circle) of seats in order with a
  "Pack 1 passes left · Pack 2 right · Pack 3 left" line. Team drafts show the team name per seat.
  Data: events-engine `{action: "standings"}` now returns `seating` (same shape as pods above; null for
  non-draft events) and `teams` (see §4). Or derive from participants (`pod_id`, `seat`) + `pods`.
- Note under the list: "Round 1 pairs across the table: 1 v 5, 2 v 6, 3 v 7, 4 v 8."

Pairing now always goes through events-engine `pair_round` (web too — stop pairing in the browser).

## 4. Team events (team_size 3 or 4)
Organizer **Teams** tab (replaces nothing; sits next to Players) while status setup/seated and before round 1:
- Lists teams (`rpc get_event_teams(p_event_id)` → `[{id, name, order, members:[{participant_id,
  display_name, slot, user_id, status}]}]`, slot 1 = seat A) and an "Unassigned" section.
- **Randomize** → `rpc randomize_teams(p_event_id)` (returns the same list). Players left over stay unassigned.
- Manual: tap a player → choose a team (action sheet / dropdown); rename a team (≤ 40 chars); "+ Team".
  Save the whole layout with `rpc set_teams(p_event_id, p_teams)` where
  `p_teams = [{"name": "Team 1", "members": ["<participant_id>", ...]}, ...]` (member order = slot order).
  Team draft allows exactly 2 teams. Max members per team = team_size.
- Pair round 1 is blocked by the server until every active player is on a team ("2 players aren't on a team yet").
After round 1 the Teams tab is read-only.

**Standings for team events**: team table first, individual table below.
- Data: events-engine `{action:"standings", event_id}` → `teams: [{rank, team_id, name, points, wins, losses, draws,
  byes, match_wins, gw, members:[{participant_id, display_name, slot, match_wins, status}]}]` plus the usual
  `standings` (individuals). Web may compute both locally with `lib/teams.ts` (same rules).
- Team row: rank · name · points · W-L-D (team) · "N match wins". Under it, members with slot letter and their
  individual match wins. Order: team points, then members' total match wins, then game-win %.
- Individual table: as today, with the team name as a tag.
- Player screen: shows "Team <name> · seat B" in the subtitle.

## 5. Life tracker
### Entry points
- Events top bar **Life** → local tracker (no event, no sync). Players named "You" / "Opponent".
- Player event screen and the Live card: **Open life tracker** for the current non-bye match.
- Mode (see below) = tracker: auto-open goes to the tracker instead of the event screen.

### Layout (portrait, full screen, no tab bar)
- Screen stays on while visible: iOS `UIApplication.shared.isIdleTimerDisabled = true` (reset on disappear);
  Android `Modifier.keepScreenOn()`/`FLAG_KEEP_SCREEN_ON`; web Screen Wake Lock API (`navigator.wakeLock.request('screen')`,
  re-request on visibilitychange; ignore if unsupported).
- Two halves. **My half at the bottom**, opponent's half at the top **rotated 180°** (both have full controls).
  In synced sessions "my side" = `my_side` from the server (organizer watching: side 0 at the bottom, read-only).
- Design source (2026-10-14): Figma "Life tracker — On its own" (73:5420) with components `Me` (Counters=0…3),
  `Counter Column`, `Increment Button` (State), `Lifetracker Info` (Clock=Normal/Warning/Overtime), `Strip Button`,
  `Counter Picker`, `Counter Toggle`; examples "Life tracker — Counters" and "— Counter picker open".
- Each half (`Me`): the life total (SF Mono Semibold 162, white; Error colour at ≤ 0) over two full-width tap zones:
  **top +1, bottom −1** in that player's orientation. Pressed zone = surface fill (150 ms). A tap fires on
  release; moving > 10 pt cancels it; press-and-hold fires after 0.5 s, then every 0.15 s. A 26×1 surface
  hairline sits 8 pt from the strip. No names, glyphs or pending badge.
- **Counters**: swipe down on a half (in that player's orientation) to open the Counter Picker inside that half;
  swipe up or Done closes it. Up to **3** counters per side; with three on, the rest show disabled ("Max 3").
  Enabled counters become columns: life keeps 50% of the width, counters split the rest, each with its own
  top +1 / bottom −1 zones and an uppercase label (Experience → "Exp"). Number sizes 120 (life) / 80, 64, 44 for
  1 / 2 / 3 counters, shrinking to fit. A counter shows when turned on or when it isn't zero (so poison you
  dealt shows on the other phone) unless turned off; this is a per-device display choice kept per match.
  Counters: `poison` (Poison, lose at 10 — the value shows in Error), `energy`, `experience`, `rad`, `speed` (0–4).
- Center strip (`Lifetracker Info`, not rotated): row 1 = round clock (left) and "R2 | Table 13 | Kai Budde"
  (right, disabled colour, truncates; status such as offline or a sent report replaces it); row 2 = 4 px bar
  (time left ÷ round length); row 3 = **Close** · **Record** · **History**. Clock: teal > 10:00 left, amber
  ≤ 10:00, Error pink in overtime as "+0:42" with a full bar. No clock (local, or no round): no time, empty bar.
- Record turns accent when a side has lost (life ≤ 0 or poison ≥ 10) and then opens the confirmation pre-filled.
  Hidden when watching read-only.
- History panel footer holds what the ⋯ menu had: Reset game, Starting life (local), New match (local), Report now.
- iOS: `rotationEffect` turns drawing but not touch areas, so the opponent half is laid out in screen order
  (zones, columns and picker rows reversed) with only the text rotated. Web and Android rotate the whole half.

### Rules
- Starting life 20 (local sessions can change it; synced sessions use the server's `starting_life`).
- Totals for a game = starting value + sum of deltas for that game (life starts at starting_life; other counters at 0).
- A **change group** = consecutive taps on the same side + counter where each tap is < 2.0 s after the previous one.
  Any tap on another side/counter, or 2 s of quiet, closes the group. History shows one entry per group.
- Every tap is an op `{client_op_id: uuid, game_no, side: 0|1, counter, delta: ±n, tapped_at: ISO}`; a group is
  derived for display, never stored. Hold-repeat taps are individual ops.
- History (sheet): per game, newest first: "Marcus · Life −5 → 15", time, and "by you"/"by Marcus" in synced
  sessions (`mine` flag on server ops). **Undo last** removes the newest group by pushing the inverse op(s).
- Losing condition: when a side's life ≤ 0 or poison ≥ 10, **Record** turns accent and opens the Record game
  flow pre-filled (no banner).
- **Record game** flow: choose winner (`Me` / `<Opponent>` / `Draw`) → confirmation dialog:
  "Record game 2: you won? Match is 2–0." with Cancel / Record. Only after Record:
  - synced: `rpc tracker_record_game(p_session_id, p_game_no, p_winner_side, p_draw)` → full state.
  - local: stored on device.
  Then the next game starts at starting life; history of earlier games stays (grouped by game).
- **Match decided** (someone has 2 game wins, or 3 games played, or the player taps "Report now" in History):
  prompt "Report 2–1 to the event?" → existing `report_match` with the side-oriented scores
  (my wins, their wins, draws) — the opponent confirms/disputes as today. Local sessions just show the result.

### Sync (synced sessions only)
- Open: `rpc tracker_open(p_match_id uuid, p_starting_life int default 20)` → state:
  `{session_id, match_id, event_id, starting_life, my_side (0|1|null), names:[side0, side1], event_name, round,
   table, clock, games:[{game_no, winner_side, is_draw, recorded_at}], ops:[{client_op_id, game_no, side, counter,
   delta, tapped_at, mine}]}`. `clock` (2026-10-14) = `{round_id, timer_status, timer_last_started_at,
   timer_remaining_at_change, timer_duration_seconds}` or null.
- Current game = number of recorded games + 1.
- Push: batch local ops every 300 ms (and on background) with `rpc tracker_push(p_session_id, p_ops jsonb)` →
  `{inserted, game_no}`. Ops are idempotent by client_op_id; keep unsent ops in a local queue (persisted) and
  retry with backoff; ops for already-recorded games are ignored by the server.
- Live: subscribe to Postgres changes `INSERT` on `public.tracker_ops` filter `session_id=eq.<id>` and on
  `public.tracker_games` filter `session_id=eq.<id>` (RLS limits rows to the two players + organizer). Merge
  incoming ops by client_op_id (ignore ones already applied locally). On reconnect, re-fetch `tracker_state(p_session_id)`.
- Clock: on the same channel, Postgres changes `UPDATE` on `public.rounds` filter `id=eq.<clock.round_id>`; the row's
  `timer_*` columns replace `clock`.
- Organizer opening a match's tracker sees it read-only (my_side null; pushes are refused server-side).

### Mode setting
`public.user_settings (user_id, tracker_mode 'elsewhere'|'tracker', updated_at)` — own row via RLS
(upsert `{user_id, tracker_mode}` on conflict user_id). Default `elsewhere`.
- Account → Settings: "Track games" `Here in the app (life tracker) | Elsewhere` (segmented / radio).
- Event screen (player): a small switch "Use life tracker" bound to the same setting.
- `elsewhere` (default): live card and auto-open lead with recording the match result (today's behavior);
  "Open life tracker" is a secondary action.
- `tracker`: live card primary action is **Open life tracker**; auto-open (once per launch/foreground while
  a round you play is running) opens the tracker for that match; result buttons move to secondary.
