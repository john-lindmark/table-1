# Scan the QR, make an account, take the seat (2026-10-23)

An organizer shows the event's join QR (`/j/<code>?s=<secret>`, from `get_join_qr`). Someone with no account scans it
with their phone camera and is playing in the event a minute later, on whichever client they have. All three clients,
no server change. Cases: `testdata/join-preview/cases.json` (iOS `JoinPreviewTests`, web `joinPreview.test.ts`,
Android `JoinPreviewTest`).

## The flow (already in place before this change)
1. **Scan.** The QR is a table-1.site address (contract/universal-links-2026-10-22.md): the app opens it when it's
   installed, otherwise the phone's browser shows the web page.
2. **Sign in = sign up.** Signed out, the page/app offers Continue with Apple, Google or email. Each one makes a new
   account if there isn't one (email: `signInWithOtp` with `shouldCreateUser`; contract/email-sign-in-2026-10-15.md).
   The web also offers Join as guest (a name only, no account).
3. **Name.** New email accounts add a first and last name before anything else (Apple and Google bring theirs).
4. **Seated.** The held QR join runs (`join_event_qr`) and the event opens. Web OAuth and the email link come back to
   the same `/j/` address; in the apps the join waits in memory through sign-in.

## New: say which event it is
Signed out, and on the name step, a **Joining** header sits under the mark:
- The event's name and one facts line: format · venue · `Run by <organizer>` · `N/cap players` (`1 player`,
  `N players` without a cap). Blank parts are left out.
- From `event_preview(p_code)` by the QR's code (anon; open, non-private, non-demo events; rate-limited per address).
  Nothing to show (private, cancelled, unknown code, offline) → `Event <CODE>` and no facts line.
- Under it: "New to Table 1? Any option below makes your account. You're seated as soon as you're in." On the name
  step: "Add your name and you're in."
- Formatting is one pure function per client (`JoinPreview` / `joinHeader`) against the shared cases.

## Get the app (web → app, through the install)
No deferred deep linking service and no fingerprinting: the **account** carries the event. Cases:
`testdata/app-handoff/cases.json` (web `appHandoff.test.ts`, Android `InstallReferrerTest`).
- **Web, after joining.** On the player screen, a signed-in player on a phone's browser (iPhone/iPad or Android user
  agent), while the event is in setup, seated or in progress, sees **Get the app**: "Your seat is on your account. In
  the iPhone/Android app, sign in the same way and this event is waiting on your Events tab", the sign-in to use
  (`Continue with Apple` / `Continue with Google` / `Continue with email: <address>`, from the account's provider), and
  Not now | Get the app. Not now hides it on that browser for good (local storage). Hidden for guests (their seat is a
  token in that browser, not an account), on computers, and while that phone's store link isn't set.
- **Store links** come from the web build's env: `VITE_IOS_APP_URL` (the App Store page, or a TestFlight public link
  until then) and `VITE_ANDROID_APP_URL` (the Play listing). Empty = hidden for that phone. Both empty today.
- **Android also carries the event through the install.** The Play link gets
  `&referrer=` + encoded `t1=<encoded /p/<event id>>`. On its first launch after install the app reads Play's Install
  Referrer once (`InstallReferrer.readOnce`; retried next launch only if Play was unavailable) and opens
  `https://table-1.site/p/<id>` like a tapped link: signed out, it signs in first, then opens the event. Only an event's
  `/p/<id>` is accepted; any other referrer (organic installs, ads, anything malformed) is ignored. A link that arrived
  with the launch (a tapped QR) wins over the referrer.
- **iOS has no install referrer.** The account is the handoff: signed in the same way, the event is already on the
  Events tab (and auto-opens while its round runs).

## Enter or paste a code (2026-11-09)

A friend's notes: "Ability to paste code to join · Paste from pasteboard shortcut". The web home already had an event
code box; the apps had none (QR, Nearby and links only).
- **iOS and Android Events home**: under Scan QR · Nearby (and on the empty home under Find nearby) a row: the code
  field ("EVENT CODE", 4 letters and digits, capitals), **Paste** while the pasteboard holds text and the field is
  empty, and **Join** (white when the code has 4 characters, flat `#545461` before). Join calls `join_event`
  (`Repo.joinByCode(code, via: "code")`) or, for a pasted QR link, `join_event_qr`, then opens the event; the server's
  refusal shows under the row. Paste reads the clipboard (iOS asks Allow Paste once), finds the code and joins at once.
- **Web**: the existing box gains **Paste** (`navigator.clipboard.readText`; a browser that refuses says to paste into
  the box) and reads a pasted message or link in the box itself; a QR link goes to `/j/<code>?s=…`, a code to
  `/join/<code>` as before.
- **What counts as a code** (`JoinCode.parse` / `parseJoinCode`): a table-1.site link wins (`/j/<code>?s=<secret>` is the
  QR's own join, `/join/<code>` a code; any other table-1.site page has none); else the whole text without spaces and
  dashes when it's 4 letters or digits; else a 4-character word right after "code" ("Code: K7PQ", "code is k7pq");
  else a word of 4 capitals and digits from the code alphabet with a digit in it ("Draft tonight! K7PQ"), never from
  inside another site's link. Cases `testdata/join-code/cases.json`, reference `testdata/join-code/make_cases.py`.
- Telemetry: `join_code_pasted` {via: paste | field, found}; `event_joined` {via: code} (apps) or `{via: qr}` for a
  pasted QR link on iOS (`paste`).

## Telemetry
- `join_prompt_viewed` `{event: bool}` when the signed-out header shows (`event`: whether the preview named the event).
  With `signed_in`, `name_added` and `event_joined` `{via: link}` this is the scan → account → seat funnel.
- `app_handoff_shown` `{platform: ios | android}` / `app_handoff_tapped` `{platform}` (web, Get the app).
- `link_opened` `{to: event, via: install_referrer}` (Android, the event a Play install carried).

## Not covered
- Private events show only the code (event_preview doesn't accept the QR secret). Showing them would need
  `event_preview` to take `p_secret`.
- No store listings yet: until the env links are set, phones without the app use the web page and see no Get the app.
- Web guests (no account) aren't handed off: their seat lives in that browser.
- An App Clip (scan → sign in → seated, no install) would be the fuller iOS answer; it needs App Store distribution.
