# Decks and cubes: client contract (L3, 2026-10-15)

Server: migration `20261015140000_card_lists.sql`. Every client (iOS, web, Android) reads and writes lists through these RPCs, so a list made or edited on one device shows on all of them after a sync.

## Model
- **List:** `{id, kind: deck|cube, name, format, versions[]}`. The `id` is a UUID the client generates, so creating is idempotent and can show immediately.
- **Versions:** oldest first. The current contents are the newest version. History is never rewritten:
  - edits within 10 minutes of the previous edit extend that version
  - anything later starts a new one
  - restoring appends a copy of the old version ("Restored vN")
- **Version shape:** `{version, note, at (epoch seconds), entries: [[card_id, board, qty], …]}`.
- **Boards:**

  | Value | Shown as | Applies to |
  |---|---|---|
  | `main` | Main deck / Main | decks and cubes |
  | `side` | Sideboard | decks only |
  | `maybe` | Considering | decks and cubes |
  | `commander` | Commander | decks only |

  Considering never counts as missing and never counts against the copies you own.

## RPCs (authenticated)

| Call | Does |
|---|---|
| `list_create(p_id, p_kind, p_name, p_format, p_entries?, p_note?)` | Creates the list as v1. Calling again with the same id returns the existing list. |
| `list_edit(p_list_id, p_ops)` | `p_ops`: `{card_id, board, delta}`, `{card_id, board, qty}` (0 removes) or `{card_id, from, to}` (move every copy). Up to 2000 ops. |
| `list_restore(p_list_id, p_version)` | Appends a copy of that version. |
| `list_update(p_list_id, p_name?, p_format?)` | Renames or changes the format. |
| `list_delete(p_list_id)` | Deletes for every device; other devices learn about it on sync. |
| `lists_changes(p_after, p_limit=100)` | `{lists, next, more}`: lists changed after the cursor, each with every version; deleted ones arrive as `{id, deleted: true}`. |

Every write returns the whole list as the server now holds it. Replace the local copy with it; the server decides the version grouping.

## Sync
Keep `cursor`, the highest `seq` applied, per account, and a device cache of the lists. Sync on app open, on returning to the Library and on returning to the foreground: call `lists_changes(cursor)` until `more` is false. Show a change at once if you like, but always replace it with the server's answer, and on an error re-sync.

## Rules the server enforces
- A cube has no sideboard or commander.
- Every `card_id` must be a known printing.
- At most 999 copies per line, 1000 lines per list, and 500 lists per account.
- Account deletion removes all lists.

## Display
Group lines by section, then by type for decks (Creatures, Planeswalkers, Instants, Sorceries, Artifacts, Enchantments, Battles, Lands, Other) or by color for cubes (White, Blue, Black, Red, Green, Multicolor, Colorless, then Lands). The grid view keeps the same headers.

## Finishes and printings (2026-10-15)

- An entry is `[card_id, board, qty]` (non-foil) or `[card_id, board, qty, finish]` (`foil` / `etched`). A line is printing × section × finish, so a deck can hold 2 foil and 2 non-foil copies of one printing as two lines. Three-element entries (all history before this change) mean non-foil. The finish must exist for that printing (`cards.finishes`), else `list_edit` / `list_create` refuse with "That printing doesn't come in that finish".
- Every `list_edit` op takes an optional `finish` (default `nonfoil`): `{card_id, board, finish?, delta | qty}`, `{card_id, finish?, from, to}`.
- New op `{card_id, board, finish?, to_card_id?, to_finish?, qty?}` moves `qty` copies (default all) of a line to another printing and/or finish in the same section. Clients use it from **Change printing or finish** (edit mode → tap a line): pick how many copies, then a printing's finish. Same printing + another finish splits the line.
- Missing counts a line as covered only by owned copies of that printing **in that finish** (collection rows are already printing × finish × condition × language).
- `card_list_entries` has a `finish` column; its key is `(list_id, board, card_id, finish)`.
- Lists and finders add cards as non-foil of the original paper printing by default (catalog contract, `original`).
