# Widgets batch: organizer Live Activity, Next event, Collection value, quick controls (2026-10-22)

iOS first (build order). Android built 2026-10-29 (§ Android); web has nothing (no widgets). Server change: the organizer Live Activity only
(migration `20261022170000_organizer_live_activity.sql`, `live-activity` edge function v6; both live 2026-10-22).

## Organizer Live Activity

Who: every account in `event_members` for the event (owner and co-organizers). An organizer who also plays gets
both activities (the player one is theirs as a player); either can be swiped away on its own.

What it shows (Lock Screen, StandBy, Dynamic Island):

- Event name, `R3/4`, the round clock (same rules as the player clock: hidden when the event's Round timer is off,
  frozen when paused, red past zero).
- **Results**: `5/8 in` as a hairline bar of one tick per match (accent = in), plus `1 dispute` in red when any.
  "In" means not pending and not an open dispute (the same `outstanding` rule as the organizer screen's big action).
- **Next step**, one line: `Waiting on 3 results` · `2 to enter yourself` (guest-only pending matches, which the
  organizer keeps score for) · `1 dispute to decide` · `Ready: Pair round 4` / `Ready: Finish event` (accent).
- Between rounds (round recorded, next not paired): `Round 3 recorded · Pair round 4`.
- Tap anywhere: opens the event (organizer screen, Live tab). Nothing is changed from the Lock Screen: pairing and
  deciding disputes need the full screen.

Starts when a round starts (push-to-start, or the app's own fallback while open), keeps through "between",
ends when the event completes or is cancelled (dismissed 30 min later), or is ended at once by the organizer
swiping it away.

Alerts (organizer only, with the update push): `Dispute at table 4` when a match becomes disputed;
`All results in · Pair round 4` / `· Finish event` when the last outstanding match of the round settles. No alert on
round start (the organizer just paired it).

### Wire

ActivityKit decodes pushed content with a plain JSONDecoder, so names are camelCase and times Unix seconds.

`OrganizerActivityAttributes { eventId, eventName }`, `ContentState`:

| field | |
|---|---|
| `phase` | `live` (a round is active) · `between` (no active round, event in progress) · `complete` · `cancelled` |
| `round`, `rounds`, `roundSeconds` | current (or last) round number, rounds planned, round length |
| `endsAt?`, `pausedRemaining?` | as the player activity; absent when not live or clocks are hidden |
| `matches` | non-bye matches in the round |
| `done` | of those, settled (`matches − waiting`) |
| `waiting` | pending, or disputed and not confirmed |
| `disputes` | disputed and not confirmed (part of `waiting`) |
| `guestWaiting` | pending matches with no account on either side |
| `players` | active players |
| `updatedAt` | |

Tokens: `live_activity_tokens.kind` gains `org_start` (per-device push-to-start for the organizer type; a new one
retires the device's older one) and `org_update` (per activity; `event_id` required and the caller must be in
`event_members`, else 42501). `register_live_activity_token` takes them; nothing else changes for players.

`live-activity` `state` returns `{ snapshots, organizer: [{ eventId, eventName, state }] }` (events you organize that
are seated or in progress, newest 3; demo only for testers). Older apps ignore `organizer`.

Dispatch: `t1_private.live_dispatch` now also fires when an organizer of the event has a token. `live_on_matches`
adds `disputed` (a match became disputed) and `settled` (a match left `waiting`) to the `match` dispatch.
Per kind, organizers get: `round_started` update, or start when they have no activity · `match` update (alerts
above) · `round_recorded` and `clock` update · `dropped` update at priority 5 · `event_ended` end.

## Next event widget (Home small/medium, Lock Screen rectangular/inline)

One event, picked in this order: an event you organize or play that is live; else the soonest upcoming with a start
time; else an upcoming one with none (newest first). Cancelled and past never show. Pending invites show as a count.

- Small: format label, name, `In 2h 10m` (within 12 h), else `Sat 6:30 PM` (within 6 days) or `Oct 30 at 12:00 PM`, in the phone's
  locale; `Starting now` once the time passes; no time: `Not scheduled`, venue, `6 players`, `Organizing` when you are.
- Medium adds the next one after it and `2 invites`.
- Live event: `Live · R2/4` in accent (the Current match widget covers your own match).
- Empty: `No events coming up` + `Create or join one`.
- Tap: that event (`table1://event/<id>?src=widget_next`); empty or invites: Events tab (`table1://events`).

Data: the same `events_home` RPC the Events tab calls, from the extension (shared sign-in), at most every 15 min,
8 s timeout, cached in the App Group (`next.events.v1`) and refreshed by the app whenever the Events tab loads.
Reloads: 1 min after a start time passes, else 30 min while an event is within 12 h, else 3 h.
Demo events only where the app shows them (TestFlight/Xcode).

## Collection value widget (Home small/medium only)

Total USD value of your collection, the change over 7 days and a sparkline of daily values (30 days, one point
per day, the last value seen that day). Not on the Lock Screen: values are private, and the views are marked
`privacySensitive` so they redact when the device is locked.

- The change includes cards you added or removed, so it says `7 days`, not "market".
- No history yet: just the value and `From today`.
- Medium adds distinct cards and total copies.
- Tap: Collection tab (`table1://collection?src=widget_value`).

Data: `library_summary_get` (nightly revalue after the price sync), from the extension at most every 6 h, or the
summary the app already holds whenever the Library syncs. Points live in the App Group (`value.points.v1`, per
account: switching accounts starts fresh; sign-out clears them). Logic: `ValueHistory` (record, change, points).

## Controls (Control Center, Lock Screen, Action Button)

Two controls and two App Shortcuts (iOS 17: Shortcuts and the Action Button; iOS 18: also Control Center and the Lock
Screen control slots):

- **Life tracker**: opens a local life tracker straight away (same as Events → Life tracker).
  `table1://tracker`.
- **Scan cards**: opens Collection → Add cards with the scanner already up; scanned cards add as one batch with Undo,
  as today. `table1://scan`.

Signed out, both open the sign-in screen. Each opens the app (`openAppWhenRun`), so there is no extension work.

## Android (2026-10-29)

John: "build the same functionality for the widgets and live activities in iOS into the similar technology for Android."

- **Live Activities → a live notification** per live event (`util/LiveUpdates.kt`), silent channel **Live events**
  (low importance; alerts stay ordinary pushes). Player: `R2/4 · T3 · vs Ana`, the status line, ranks and records, the
  round clock as a countdown chronometer (paused: `paused 12:00`), and **Won 2–0 / Won 2–1 / Other result** while the
  match is pending, **Confirm / Dispute** when the opponent reported (a broadcast receiver calls `report_match` /
  `respond_to_result`, then reads the state again). Organizer: `Friday Modern · R2/4`, `5/8 in · Waiting on 3 results`
  with a progress bar, the flags (disputes, results to enter), the clock. Tap: the event. Over (complete, cancelled):
  the last line stays 30 min, then goes; dropped goes at once. On Android 16 both ask to be promoted as Live Updates
  (`POST_PROMOTED_NOTIFICATIONS`, `android.requestPromotedOngoing`).
- **Feeds:** every `live-activity` `state` read (the Events tab, the app coming back, a push about an event arriving,
  a widget refresh) and `live.player` / `live.organizer` FCM messages: `live-activity` dispatch sends each Android
  device (`devices.platform = android`) of the players whose state changed and of every organizer a data-only
  message `{kind, event_id, event: start|update|end, live: "<JSON {eventId, eventName, participantId?, state}>",
  title, body}`; players' are silent (notify-worker already alerts rounds and results), organizers' carry the dispute
  / all-results-in alert (`live-activity/android.ts`). Migration `20261030040000_live_dispatch_android.sql` lets the
  dispatch guard count Android devices (an all-Android event never reached the function).
- **Widgets (Glance, `widgets/`):** Next event, Collection value and Current match, small and medium, same content
  and pick rules as iOS (`data/LiveSurfaces.kt`, tests `LiveSurfacesTest`, the cases of iOS `WidgetLogicTests`).
  Current match ticks the round clock (a Chronometer in RemoteViews) and reports, confirms or disputes from the
  medium size. Data on the device (`t1.widgets`): written by the app when it reads the same things, fetched by a
  widget when stale (15 min / 6 h / 5 min, 8 s limit); cleared at sign-out. Android has no lock screen widgets: the
  live notification covers the match there.
- **Look and sizes (2026-10-30).** John: "the android widgets don't appear to match the UI from the iOS ones, also I
  should be able to change the size to be full width and taller and smaller." The widgets now draw iOS's layouts
  (`widgets/WidgetViews.kt`, after iOS `Shared/WidgetViews.swift` and `MatchWidget.swift`): labels in uppercase mono
  with iOS's tracking (a RemoteViews TextView, since Glance text has no letter spacing), the same order and sizes
  (Next event: format, when, Organizing, then name and venue at the bottom; Collection value: value and `+$87.42 · 7
  days` in accent/red at the bottom, whole dollars from $1,000, the line under it; Current match: wins on the accent,
  Dispute | Confirm 2–1), the launcher's own corners and 14–16 dp padding. They resize from one row to the full
  width and any height (`minResizeHeight` 40 dp, no maximum; `SizeMode.Exact`), with a layout per shape
  (`WShape`: one-row strip below 110 dp, square/band below 190 dp, tall from 190 dp; wide from 240 dp):
  - **Strip (2×1, 4×1):** Next event when + name (wide: format, when | name, invites or venue); Collection value
    and amount (wide: amount, the line, the change); Current match where + clock (wide: where, opponent | clock).
  - **2×2 and 4×2:** iOS's small and medium.
  - **Tall (2×3+, 4×3+):** Next event lists the later events that fit under the first (each opens its own event,
    `+N more`); Collection value grows the amount and the line; Current match gets the big clock, the status line
    and all five result buttons (narrow: Confirm above Dispute).
  Glance draws at most ten children in a column, so the layouts group their rows. Design QA without a phone:
  `./gradlew testDebugUnitTest -PT1_WIDGET_GALLERY --tests '*WidgetGalleryTest'` draws every widget at every shape
  (Robolectric, native graphics) to `app/build/widget-gallery/`; it is left out of the normal test run. Rules tested
  in `WidgetLayoutTest`.
- **Controls → Quick Settings tiles and launcher shortcuts:** Life tracker and Scan cards (`table1://tracker`,
  `table1://scan` → Add cards with the scanner up). `control_used` gains `surface: tile | shortcut`.
- `table1://event/<id>`, `events`, `collection`, `tracker`, `scan` (with `?src=`) open in MainActivity
  (`WebLink.parseApp`, `AppLinkTest`); `surface_opened {source}` as on iOS. New telemetry: `live_activity_action
  {action: report | confirm | dispute, surface: notification | widget}`.

## Meta widgets (2026-11-02; iOS and Android)

John: "build a meta breakdown widget for both platforms. Include the graph for the medium and larger sizes. add
different colors for each item. also make a matchup grid widget. and a matchup widget for a specific archetype", and
"user can set the format in the widget settings". Three home screen widgets on Insights' constructed packs; no server
change, no sign-in needed (the packs are public).

- **Settings** (iOS: long press → Edit Widget, `AppIntentConfiguration`; Android: `MetaWidgetConfigActivity`, opened when
  the widget is placed on Android 11 and older and from Reconfigure / the widget's settings on 12+, where it's placed on
  the defaults, `configuration_optional`): **Format** (Standard … Canadian Highlander), **Events** (Big events | All
  events), **Window** (7 / 14 / 30 / 90 days); Archetype matchups also **Archetype** (the format's archetypes, those
  with matchups first, most played first, then the rest by name; never Other). Defaults: Modern, Big events, 30 days,
  the most played archetype. A pick from another format (the format changed after) is ignored: the most played shows.
  Android keeps picks per widget id (`t1.widgets.meta`, not cleared at sign-out; removed with the widget).
- **Events:** Big events falls back to All events when its window has no decks (`tierFor`); the label says which.
- **Colors** (each archetype its own): the eight largest named archetypes of the picked window get the dataviz
  reference palette's eight dark categorical colors in order (`#3987E5 #D95926 #199E70 #C98500 #D55181 #008300
  #9085E9 #E66767`, run through its validator on `#171725`: lightness band, chroma, color-blind and normal-vision
  separation, 3:1 contrast all pass); everything else grey `#6E6E7E`. The same picks give an archetype the same color in
  all three widgets. Names always sit beside their swatch, so color never carries identity alone.
- **Meta** (iOS small / medium / large; Android every size): a label (`MODERN · BIG · 30D`, deck count from medium up),
  a share bar (each archetype in its color, the rest grey, 2 pt apart), the largest archetypes with their share
  (small 5, medium 5, large 8). **Medium and larger add the graph:** Meta over time for the listed archetypes over the
  window (the pack's daily 7-day shares cut to the last 7/14/30/90 days), each line in its color, largest on top, two
  gridlines, dates that never collide. Large rows add the change on the window before (▲ accent / ▼ pink) and the win
  rate. Android also has a one-row strip (top archetype; wide: the top two) and a tall narrow layout (graph, bar, rows).
- **Matchup grid** (iOS medium / large; Android two rows and up): the picked window's grid (else the pack's 90-day All
  events grid, as the Insights tab), the most played columns that fit (iOS 6 / 7, Android up to 9) and the first rows
  (iOS 5 / 12, Android as many as fit), cells with the Insights tab's `heat` (accent up, pink down, faded under 30
  matches), columns by short code (`codes`: initials, one word its first three letters, clashes made unique) over a
  2 pt line in the archetype's color; rows by name (narrow: code) with their swatch.
- **Archetype matchups** (iOS small / medium / large; Android every size): the archetype's match win rate, its share
  and record; small adds its best and worst matchup, medium **Good against** / **Bad against** (20+ decided matches,
  above / below 50%, three each, never Other: the deck screen's rule), large and tall every matchup with matches in
  the grid's order, as a bar from 50% (right accent, left pink, full at 25 points), the percent and the match count.
- **Tap a square** (2026-11-02, John: "tap different cells and it shows details similar to in the app"): a grid
  square is a button (iOS `Button(intent: MetaSelectIntent)`, Android `MetaSelectAction`). The tapped square is
  outlined, its row name and column code sit on the lighter surface, and the label line becomes the app's wording
  (`cellDetail`, cases `cell_detail`): "Broodscale Combo vs Izzet Prowess" with the record ("321-236-14") at the end,
  and on large / tall grids a second line with the win rate and likely range ("57.6% · likely 54%–61%", or "Only 2
  matches: too few to say"). The same square again lets it go; another square moves it. A pick shows only while its
  square is on the widget.
- **Tap a legend row** (John: "tap the legend items in the metashare charts and it dims the other lines"): on Meta
  from medium (Android 4×2 and tall) up, a row is a button; its line is drawn on top at full strength (2 pt) and the
  other lines, rows and share-bar parts fade (lines to 20%, rows to 40%). Again lets it go. Small and the one-row
  strip have no graph, so nothing to pick.
- **Where a pick lives:** iOS keeps it in the App Group per widget kind and picks (`MetaSelection`, key
  `<meta|grid>|<format>|<tier>|<days>`): an intent can't name the widget it's on, so two widgets with the same picks
  share it. Android keeps it per widget id (`sel.<id>` in `t1.widgets.meta`), cleared when the widget's settings are
  saved or it's removed. Rule `toggled` / `cellOf`, tested on both. Android sends `widget_tapped {widget, what:
  cell|row}`; iOS intents run in the extension, which has no telemetry.
- **Tinted and clear Home Screens** (iOS 18+, John: "tinted widget looses readability"): the system drops every color
  and keeps only opacity, so a strong teal square turned into a solid white block under white text. With
  `widgetRenderingMode == .accented` the widgets draw their own way (`MetaLook.slot/fill/outline/ink`): archetypes in
  white fading by place (100% for the largest, −9% a place, never under 35%), winning squares filled faintly (12% +
  20% × strength), losing squares outlined instead (30% + 40% × strength), even squares 10%, text always full (dim
  squares 55%), the tapped square framed. Archetype bars: winning white, losing 45%. Debug gallery
  `-T1WidgetsDemo tinted` draws them through a luminance mask, as the Home Screen would. Android widgets keep their
  own dark background, so they have no tinted mode.
- **Taps** open Insights on the widget's picks: `table1://insights/<format>?tier=&days=&src=widget_meta`, `/matchups`
  (`widget_grid`) and `/archetype/<id>` (`widget_archetype`); iOS `PushRoutes.insightsWidget` → `InsightsPush` (tier
  and days set on the store), Android `WebLink.Insights` (picks set, then the grid or archetype route).
- **Data:** the widget fetches its format's pack itself (`…/storage/v1/object/public/catalog/insights/constructed/<format>.json`)
  at most every 3 hours with If-None-Match and an 8 s limit, and redraws every 3 hours (packs build every 6): iOS
  App Group `meta/<format>.json` (`MetaPackStore`), Android `files/widgets/meta-<format>.json` (`MetaPacks`). Only
  the parts the widgets read are decoded (`MetaPack`). No pack yet and offline: "Modern loads when you're online".
- **Logic** is shared: Python reference `testdata/meta-widgets/make_cases.py` over the live Modern pack of 2026-11-02
  (`modern.json`) → `cases.json`; iOS `Shared/MetaWidget.swift` (`MetaWidgetTests`), Android
  `widgets/MetaWidgetData.kt` (`MetaWidgetDataTest`). `InsightCharts.swift` moved to `Shared/` so the extension has
  `heat`, `window` and the percent formats.
- **Design QA:** iOS `-T1WidgetsDemo meta|grid|archetype` (DebugResources `insights-demo-widget-modern.json`), Android
  `WidgetGalleryTest.insights` (`-PT1_WIDGET_GALLERY`, sheets `meta*.png`, `matchup-grid.png`, `archetype*.png`).

## Android widgets turned into Collection value (2026-11-02)

John: "android widgets appear to switch back to collection value even though they were set as a different widget in
the past." R8 (release builds) merged `NextEventWidget`, `ValueWidget` and `MatchWidget` into one class (`qa.d` with a
`$r8$classId`). Glance's `updateAll` finds a widget's ids by its provider's class name, so `ValueWidget().updateAll()`
(every Library sync whose value changed) redrew every Table 1 widget with Collection value's content. Fixed both ways:
`proguard-rules.pro` keeps every `GlanceAppWidget` whole under its own name, and `Widgets.refresh(widget, receiver)`
redraws by the receiver's own ids instead of `updateAll`. A release build fails (`minifyReleaseWithR8` check in
`app/build.gradle.kts`) when any `GlanceAppWidget` class is renamed or merged. Widgets already showing Collection value
recover on the next build: the update the system sends after an app update redraws each through its own receiver.

## Telemetry

- `live_activity_started` / `live_activity_ended` gain `type: player | organizer`.
- Widget and Live Activity taps: `surface_opened` with `source` (`widget_next`, `widget_value`, `widget_meta`,
  `widget_grid`, `widget_archetype`, `organizer_activity`, `organizer_island`) as today.
- Android `widget_tapped` `{ widget: meta | grid, what: cell | row }` when a square or legend row is tapped.
- Android `widget_configured` `{ widget: meta | grid | archetype, format, tier, days, archetype: bool }` on Save in a
  widget's settings (iOS edits happen in the system's Edit Widget, which the app doesn't see).
- `control_used` `{ control: tracker | scan }` (Control Center, Lock Screen, Shortcuts and the Action Button alike).
- `widgets_changed` already reports which families are on the home/lock screen; iOS adds `kinds`
  (`site.table1.meta`, `site.table1.matchups`, `site.table1.archetype`, …), Android's families name the widget
  (`meta`, `matchup_grid`, `archetype`).
